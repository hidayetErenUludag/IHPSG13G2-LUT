Method

How the tables were made

Every value comes from a DC operating-point sweep of the IHP-Open-PDK model: VGS in 20 mV steps (50 mV for HV), VDS in 50 mV steps (100 mV for HV), one single-finger device per L and finger width. Between grid points the page interpolates linearly along VGS; L, VDS and Wf are grid values.

Why finger width is an axis

At the same bias, current per µm changes by about 25 % between 1 µm and 5 µm fingers, so a table built at a single width mis-sizes other widths by up to 34 % in ID. LV PMOS leaves its valid range above 10 µm. The calculator warns when rounding to whole fingers moves ID or gm more than 10 % from the target.

Accuracy

Checked against direct simulation of the rounded device: ID, gm and gds within 3 %, fT within 8 % (the table is conservative for multi-finger devices). Results are simulation only and have not been compared against measured silicon.

Conventions

Cgg includes gate overlap capacitance, so fT = gm/(2π·Cgg) matches PSP's own fug. Cdd adds the drain junction and gate-drain overlap. PMOS values are magnitudes.

Use the tables in Python

Full-precision tables, including drain thermal-noise and flicker-noise PSDs, are in npz/lut_<device>_wf<Wf>.npz, with the generator gen_lut.py beside them. For ng fingers, multiply currents, conductances and capacitances by ng.

import numpy as np
t = np.load("npz/lut_sg13_lv_nmos_wf2.npz")   # arrays shaped [L][VGS][VDS]
gm_id = t["gm"] / t["id"]                      # S/A
ft    = t["gm"] / (2 * np.pi * t["cgg"])       # Hz

Frequently asked questions

What is the gm/ID sizing method?

gm/ID sizing picks the transconductance efficiency gm/ID to set how strongly a transistor is inverted, then reads current density, intrinsic gain and fT from tables simulated with the real device model instead of square-law equations. The method is described by Jespers and Murmann (Cambridge University Press, 2017).

Which IHP SG13G2 devices does this cover?

All four MOSFETs: sg13_lv_nmos and sg13_lv_pmos (1.2 V core, L = 0.13 to 5 µm), sg13_hv_nmos (3.3 V I/O, L = 0.45 to 5 µm) and sg13_hv_pmos (3.3 V I/O, L = 0.40 to 5 µm), each at finger widths of 0.5, 1, 2, 5 and 10 µm. The *_rf_* symbols use the same transistors with an RF model and are not tabulated separately.

Why does finger width matter in SG13G2?

SG13G2 LV devices depend on finger width, not only total width: LV NMOS Vth falls from 0.29 V at a 1 µm finger to 0.21 V at a 50 µm finger. A table built at one width can mis-size other widths by up to 34 % in ID, so this tool sizes devices as ng fingers of width Wf, which scale exactly.

How accurate are the values?

Devices sized from the tables and simulated directly in ngspice agree within 3 % for ID, gm and gds, and within 8 % for fT. All values are simulation results from the PSP103 models and have not been compared against measured silicon.

Which process corner and temperature are used?

The typical corner mos_tt at 27 °C with VSB = 0, simulated in ngspice-47 with the PSP103 model from the IHP-Open-PDK. Other corners and temperatures are not included yet; regenerate the tables with gen_lut.py to add them.

Can I use the tables offline or in Python?

Yes. The offline version is a single self-contained HTML file of about 4.5 MB. Full-precision NumPy .npz tables, including noise PSDs, are in the npz folder of the GitHub repository.

Is it free to use, and how do I cite it?

Yes. Code, page and tables are released under the Apache License 2.0. Cite the Open-LUT paper by Khalid, Maestre and Madrid-Khalid (ICICM 2025), and this repository via its CITATION.cff file.
